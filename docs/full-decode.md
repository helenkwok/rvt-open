# Full decode of one file

No Revit file has been decoded completely yet, by rvt-open or any other reader. `tools/full-decode/full_decode.py` measures how far rvt-open is from that on one small file, the tiny reference model `1-hip-roof` saved in Revit 2024 (release asset `fixtures-tiny-1`, MIT), against that file's Revit API dump (5,601 elements with every parameter and property). CI runs it in the job "full decode of one tiny model" and fails when a total falls below `tools/full-decode/floor.tsv`, so coverage can only rise. When a change raises a total, regenerate the floor with `--write-floor` in the same pull request.

```bash
cargo run --release --example full_decode -- 1-hip-roof.rvt > facts.json
python3 tools/full-decode/full_decode.py 1-hip-roof.rvt 1-hip-roof.api-dump.json facts.json out/ --floor tools/full-decode/floor.tsv
```

`examples/full_decode.rs` writes what the schema reader reads (every partition object with the bytes it read and the bytes between objects, every element object's fields and stored parameters, the element table's rows) without interpreting it; the script does the accounting and the comparison. Needs `olefile` (`tools/ci/requirements-olefile.txt`).

## The three axes

**Bytes.** Every byte is `decoded` (its meaning is read and checked), `known` (the structure around it is known, its content is not read) or `unknown`, counted in three places:

- the file: the CFB header, FAT, directory, mini FAT and free sectors; sector slack past a stream's end and unused directory entries hold stale bytes that belong to no stream (`known`);
- each stream as stored: page parity (every codeword of every page is recomputed), gzip members (inflated, CRC-32 and length checked), the partition framing (segment markers whose stored sizes agree with their members, section headers, terminal), zero padding; the 64-byte signature values of partition sections and the leading word of the `Global/*` streams are `known`;
- each compressed stream inflated: partition objects through the schema (header, fields read, trailing size; bytes an object's read did not reach are `known`), the bytes between partition objects (`unknown`), the element table's rows; the other inflated streams are object graphs not yet accounted byte by byte (`known`).

**Elements.** An API element is located when the file holds an element object whose root `m_id` is its ElementId and `Global/ElemTable` has a row for it. Its class, category, is_type, name, level, host, workset, created and demolished phase, design option and UniqueId are each `match`, `differ` or `not decoded`. A file class decodes the API class when every element of that file class has the same API class. Every element object of the file that is not an API element is counted by where it lies: after the partition's first section header it belongs to an embedded content document.

**Values.** Every parameter the API reports with a value is looked up among the element's stored parameters, by its built-in id or by the id of its parameter element, and compared by storage type and value (lengths in internal feet, as Revit stores them). A value with no stored entry is `not stored`, split by whether the API marks it read-only (likely computed). Properties are compared where a file field is known for them.

## Measured

| Bytes, 1-hip-roof (Revit 2024) | decoded | known, not decoded | unknown |
|---|---|---|---|
| file container (stream sectors counted below) | 17,040 | 20,489 | 0 |
| streams as stored | 5,636,090 | 11,629 | 0 |
| inflated streams, first measure | 26,867,852 | 3,819,349 | 6,145,745 |
| inflated streams, element headers read | 33,013,573 | 3,819,349 | 24 |
| inflated streams, object graphs and schema read | 36,808,260 | 24,686 | 0 |
| streams as stored, small streams accounted | 5,641,599 | 6,120 | 0 |

The bytes between a partition's data objects are element-header records, one per element object, in runs with a start and an end marker (`schema_objects::header_records`): on this file 36,123 records and their markers fill all 6,145,721 such bytes, and every record reads through the schema. Each `Global/*` stream reads as one object graph from its first byte (`schema_objects::read_graph`), followed by a u32 0 (and, in `Global/History`, the episode list); `Global/ContentDocuments` is one record per embedded document, a key object, a u32 size, the document's graph and the size again (`schema_objects::content_documents`: 93 records, every graph read exactly); `Formats/Latest` reads to its end through the schema grammar. What stays `known`: the classes' 1,524 GUIDs in the schema stream (24,384 bytes, stepped over), the `Contents` header and member, 48 bytes of one Extensible Storage payload, the closing 14 bytes of `ContentDocuments`, the 93 partition section signatures (64 bytes each: not the MD5, SHA-1, SHA-2, SHA-3 or BLAKE2 digest of the section's stored or inflated bytes, its embedded document's record or the stream up to it, so likely keyed), 71 bytes of the `Contents` header before Revit 2025, 27 bytes of flags and integers between `BasicFileInfo`'s strings, the end bits before each stream's page parity, and the container's stale bytes. Each `Global/*` stream starts with a u64 format version, as a partition does (`ContentDocuments`, `DocumentIncrementTable` and `History` 1, `ElemTable` and `PartitionTable` 0, `Latest` 5, the same in all 220 tiny reference files, Revit 2018 to 2027); `Contents` starts with a u32 magic `0x05221962`, a format version and a 1, and ends its header with the magic again and a build number; `BasicFileInfo` is a u32 version, counted UTF-16 strings and the same facts as UTF-16 text lines; `TransmissionData` is a counted UTF-16 XML document; `ProjectInformation` is a ZIP archive whose CRCs and layout check.

All 5,601 API elements are located; the file's other 30,522 element objects all lie in embedded content documents. Category (the element header's), level, created and demolished phase, design option, workset (the element table's partition field), UniqueId (creation episode and first id) and host match on all 5,601; class on all 5,601 (a `FamilySymbol` of the room tag, area tag or generic annotation category has the API class `RoomTagType`, `AreaTagType` or `AnnotationSymbolType`; 5,423 before); is_type on all 5,601 (an element type is one whose class derives from `Symbol`; the dump marks the 169 elements whose API class is `ElementType` itself as no type, a subclass test, and the comparison reads them as types; 5,432 before); name on 4,450 (`rvt::element_names`: the element's own objects, a graphics style's category, a font element's owner; 581 before), 102 differ (32 internal dimension styles named `SecretInternal...` in the file and otherwise by the API, 14 sun settings the API names by their in-session state, 4 tile patterns, and 50 graphics styles of built-in subcategories whose help term is not the name Revit shows, such as `Fabric Reinforcement` for `Structural Fabric Reinforcement`), 1,049 not decoded: 710 graphics styles of built-in subcategories that Revit's help does not name in a table, list or label (see below), 82 legend components, 36 conceptual construction types, sketch planes, viewers and other elements whose name is not text in their own objects. Of 37,420 parameter values, 2,190 match a stored value (97 differ). Most of the rest are fields Revit shows as parameters (`rvt::field_parameters`): 16,518 match the element header's category and design option (18 differ: sub-elements whose API category is a subcategory), and 8,718 match an element field through 432 (class, parameter, field) rules measured on this file (26 of them follow a pointer into an object the element owns: a type's compound structure, a material's own object) and 50 rules that follow ids into other elements (`field_parameters::LINKED_RULES`: a text, dimension or spot style's font from its font element and its line weight and colour from its category element's first graphics style, a family type's OmniClass and structural codes from its family, a viewer's view settings from its view). 2,825 match a parameter set another of the element's objects owns (`SchemaObject::nested_parameters`: a property set's `m_oParamSet`; a structural asset's unit weight is its density times standard gravity, not the unit-weight entry the set stores), 1,399 are a type's own name (Type Name) or its family's name (Family Name, from the family element or, for a system family, from Revit's help; 12 differ, the internal styles above), and the 78 integer parameters of dimension and spot styles that sit in the Double set are read as the integers they hold (`TEXT_STYLE_BOLD`, `TEXT_STYLE_ITALIC`, `TEXT_STYLE_UNDERLINE`: kept in the Int set of some elements and as a whole-number float in the Double set of others, in 101 public samples) and match as stored values. 5,643 have no source yet (2,116 read-only): system family names (687; 193 now come from Revit's help by the types' class), project parameters found by name only (482), IFC parameters (746), Uniformat and OmniClass codes and descriptions, material transparency and smoothness (206) and others Revit keeps elsewhere. The 97 that differ are one parameter, `HEAVY_END_PEN` of arrowhead styles: the file stores 1 and the API shows 5 to 7, found in no field of the style or its own category. Every parameter has a known id: 3,119 values had a `BuiltInParameter` name the catalog did not hold, 13 names that share an id with a catalog member (`builtin_parameters::ALIASES`: names renamed in the Revit 2026 API such as `OMNICLASS_CODE`, and synonyms such as `SYMBOL_NAME_PARAM` for `ALL_MODEL_TYPE_NAME`). Of the 119,009 property values, 56,591 match a decoded field (id, level, phases, owner view, name, UniqueId, workset, design option, view-specific, pinned), 20,013 are the API's runtime state (`IsValidObject`, `IsModifiable`, ...), not file data, and 42,405 are not compared yet or have no decoded field.

What holds on all three: every element is located; the category, level, phases, design option, UniqueId and host reads; the class rule (a family type's class by its category) and the is_type rule; the `Global/*` format versions (all 220 tiny reference files); the nested parameter sets, the name-derived Type Name and Family Name, and integer parameters in the Double set (78 on each). What does not: the element table's partition field is read only from the 40-byte rows of Revit 2024 and later, so the 2021 workset is not decoded (and every element of this model is in workset 0 on every release, so neither release proves the field); on 2021, 316 values from two field rules measured on 2024 differ (`SPACE_COOLING_SET_POINT` and `SPACE_HEATING_SET_POINT`, 158 each). The Revit 2027 API names two parameters `DOOR_HEIGHT` and `GENERIC_WIDTH` (48 values, none stored under those ids), which share ids with catalog members; they are in `builtin_parameters::ALIASES`. On 2021, 18 values have a parameter name with no known id (`FAMILY_THICKNESS_PARAM`, `RBS_PIPE_ROUGHNESS_PARAM`, `RBS_CURVETYPE_ROUGHNESS_PARAM`).

## Names Revit keeps in its program

Revit does not store the names of built-in categories and subcategories or of system families in the file: it shows them from its program, in the language it runs in. `rvt::program_names` takes them from Revit 2027's public help, which offers the same topic in 13 languages (ENU, CHT, CHS, CSY, DEU, ESP, FRA, ITA, JPN, KOR, PLK, PTB, RUS): a term of a table cell, list item, UI label or bold text, taken at the same position of the same topic in each language, names only, each entry citing its topic. A built-in category is tied to its help term by its `BuiltInCategory` enum name (its words, plural forms, a leading parent category dropped; a term the help writes in angle brackets keeps them); an entry whose English term differs from the catalog's English name is left out. A system family is tied to the file class of its types, for classes whose types all belong to one system family. Names are given in the language the file was saved in (`BasicFileInfo`, "Locale when saved"), English where it stores none or the help gives none in that language. The Revit API dump only measures the result: 284 categories and 26 system families are named; on 1-hip-roof (2024) 204 more element names match and 193 more Family Name values, while 50 names differ where the help's term is not the name Revit shows. System families the help names only in running text (`Basic Wall`, `Arrowhead`, `Tag Label`, `Filled region`) are not taken.
